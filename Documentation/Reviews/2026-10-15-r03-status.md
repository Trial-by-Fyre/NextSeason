## 1. What R03 fixes

A notification used to be recorded as sent before iOS accepted it, so a scheduling failure lost it permanently. Now:

1. Delivery reports one of four outcomes: accepted, suppressed (alerts off, or an interactive refresh), failed (iOS rejected it), or unknown (submitted, result lost to cancellation).
2. On **failed** only, the saved row is put back as pending, so the next refresh retries the alert. Suppressed is consumed and never replayed. Unknown is never retried, because a repeat could alert the user twice.
3. The put-back only applies if the row is still the same saved show, still active, and still holds the decision that attempt made. It never overwrites a newer change, a removal, a pause, or a re-added show.
4. A refresh skips any show another refresh is still working on (approved revision 4 change 1).
5. Diagnostics text says what actually happened ("Notification scheduled", "Scheduling failed … will retry next refresh", and so on). It never claims the user saw an alert.
